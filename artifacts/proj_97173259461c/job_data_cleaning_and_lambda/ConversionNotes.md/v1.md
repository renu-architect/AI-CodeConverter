## Conversion Notes

### 1. Glue Context and SparkSession Initialisation

The entire Glue initialisation block (`SparkContext.getOrCreate()`, `GlueContext`, `Job`, `getResolvedOptions`) was removed. Azure Synapse Spark pools pre-initialise a `SparkSession` named `spark` in notebook environments. For Spark Job Definition (`.py`) scripts, `SparkSession.builder.getOrCreate()` is used in the `if __name__ == "__main__"` guard. No manual context wiring is required.

### 2. Catalog Read → Direct ADLS Gen2 CSV Read

`glueContext.create_dynamic_frame.from_catalog(database="payments", table_name="medicare")` has no direct equivalent in Synapse without re-registering the table in a Synapse Lake Database. The replacement uses `spark.read.csv(SOURCE_PATH, schema=SOURCE_SCHEMA, header=True)` with an **explicit schema** (`SOURCE_SCHEMA`). Declaring all columns as `StringType` upfront is intentional: it avoids the type-inference ambiguity that caused the `provider id` choice-type problem in Glue, and gives the `resolve_provider_id` step full control over the cast.

### 3. `resolveChoice(cast:long)` → `col().cast(LongType())`

Glue's `resolveChoice(specs=[('provider id', 'cast:long')])` is replaced by `df.withColumn("provider id", col("provider id").cast(LongType()))`. PySpark's `cast` returns `null` for values that cannot be converted — semantically identical to Glue's `cast:long` resolution strategy. The subsequent `filter_null_provider_ids` step then removes those nulls, exactly mirroring the original two-step pattern.

### 4. `DynamicFrame.fromDF` and `toDF` Eliminated

The round-trip conversions (`medicare_res.toDF()` and `DynamicFrame.fromDF(medicare_df, glueContext, "nested")`) are eliminated entirely. The pipeline works exclusively with native PySpark `DataFrame` objects throughout, removing two unnecessary serialisation boundaries.
