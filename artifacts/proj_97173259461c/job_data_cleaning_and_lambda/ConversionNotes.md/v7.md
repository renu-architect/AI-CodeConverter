## Conversion Notes

### Fix 1 — `schema_fidelity` (MEDIUM): Swap `resolve_provider_id` / `filter_nulls` call order in `main()`

**Root cause:** The original code called `filter_nulls(df)` first (operating on the raw `StringType` `'provider id'` column) and then `resolve_provider_id(df)`. A whitespace-only or otherwise non-numeric string in `'provider id'` would pass `isNotNull()` on the raw string, survive into the output, and then be silently cast to `null` by `LongType()` — producing a null `'provider id'` row that the original Glue job would have excluded.

**Fix applied (lines ~390–415 in `main()`):**
- `resolve_provider_id(df)` is now called **first**, casting `'provider id'` to `LongType` and converting any non-castable string to `null`.
- `filter_nulls(df)` is called **second**, operating on the already-cast `LongType` column so that both genuine SQL nulls *and* non-castable strings (now null after the cast) are excluded.
- This exactly replicates the original Glue pipeline order: `resolveChoice (cast:long)` → `Filter (WHERE provider id IS NOT NULL)`.
- The docstrings for both `resolve_provider_id()` and `filter_nulls()` were updated to document the required call order and the rationale, and the `main()` pipeline step comments were renumbered accordingly.

### Fix 2 — `input_sources` (LOW): Remove `'total discharges'` `StructField` from `SOURCE_SCHEMA`

**Root cause:** `SOURCE_SCHEMA` contained a `StructField("total discharges", StringType(), True)` that does not appear in the original Glue job's input schema contract, is never referenced in any transformation function (`filter_nulls`, `resolve_provider_id`, `strip_currency`, `nest_and_cast`), and is never written to the output. Carrying it through the DAG represented schema drift from the original pipeline contract and added unnecessary column carriage.

**Fix applied (lines ~80–92 in `SOURCE_SCHEMA`):**
- The `StructField("total discharges", StringType(), True)` entry was **removed** from `SOURCE_SCHEMA`.
- A block comment was added above `SOURCE_SCHEMA` explaining the removal and providing guidance for re-adding the field if a confirmed downstream requirement emerges in future.
- All other `StructField` entries and their existing comments are preserved unchanged.
