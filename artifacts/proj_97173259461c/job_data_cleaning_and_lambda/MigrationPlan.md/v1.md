## 1. Executive Summary

This plan describes the complete migration of the `data_cleaning_and_lambda` AWS Glue PySpark job to an Azure Synapse Analytics Spark Notebook or Spark Job Definition. The source job reads Medicare provider payment records from the AWS Glue Data Catalog, performs type resolution, null filtering, currency string cleaning via a Python lambda UDF, schema restructuring into nested structs, and writes Parquet output to Amazon S3.

The target environment replaces all Glue-specific APIs (`GlueContext`, `DynamicFrame`, `apply_mapping`, `resolveChoice`) with native PySpark equivalents available in Azure Synapse Spark pools. Data source access is migrated from the Glue Data Catalog to Azure Data Lake Storage Gen2 (ADLS Gen2) or an Azure Synapse Analytics linked service. Output is written to ADLS Gen2 in Parquet format. The `mssparkutils` library replaces AWS-specific credential and storage utilities.

The migration is classified **HIGH** complexity due to the Glue DynamicFrame API surface, nested struct construction, UDF hardening requirements, and catalog abstraction replacement.

## 2. Architecture Comparison

| Dimension | AWS Glue (Source) | Azure Synapse Spark (Target) |
|---|---|---|
| **Execution Runtime** | AWS Glue Spark Runtime (managed EMR) | Azure Synapse Spark Pool (managed Spark) |
| **Entry Point** | `GlueContext(SparkContext.getOrCreate())` | `SparkSession` (pre-initialised in Synapse notebooks as `spark`) |
| **Data Catalog** | AWS Glue Data Catalog (`payments.medicare`) | Azure Synapse Analytics Catalog / Unity Catalog / direct ADLS path |
| **Data Source Read** | `glueContext.create_dynamic_frame.from_catalog` | `spark.read.csv(...)` / `spark.read.format(...)` from ADLS Gen2 |
| **Intermediate Frame Type** | `DynamicFrame` (Glue-native) | `DataFrame` (PySpark-native) |
| **Type Resolution** | `DynamicFrame.resolveChoice(specs=[("field","cast:type")])` | PySpark `cast()` + `when()` / `try_cast()` |
| **Field Mapping / Nesting** | `DynamicFrame.apply_mapping(...)` | PySpark `select()` + `struct()` + `col().cast()` |
| **UDF Registration** | `udf(lambda x: x[1:], StringType())` | `udf(lambda x: ..., StringType())` — identical syntax, needs null guard |
| **Output Write** | `glueContext.write_dynamic_frame.from_options(format="parquet")` | `df.write.mode("overwrite").parquet(adls_path)` |
| **Storage Layer** | Amazon S3 | Azure Data Lake Storage Gen2 |
| **Credential / Secret Management** | IAM Role (implicit) | `mssparkutils.credentials` / Linked Service / Managed Identity |
| **Job Bookmarks** | Not used (non-functional in source) | Not applicable — not migrated |
| **Observability** | None in source | Add `mssparkutils` logging or Azure Monitor |
| **Notebook / Script Format** | Python script (`.py`) | Synapse Notebook (`.ipynb`) or Spark Job Definition (`.py`) |

## 3. Glue API → Synapse API Mapping

| # | Glue API / Construct | Glue Module | Synapse / PySpark Equivalent | Notes |
|---|---|---|---|---|
| 1 | `SparkContext.getOrCreate()` | `pyspark.context` | `spark.sparkContext` (pre-built in Synapse) | `SparkSession` named `spark` is auto-initialised in Synapse notebooks; no manual creation needed |
| 2 | `GlueContext(sc)` | `awsglue.context` | **Remove entirely** | No equivalent; all functionality replaced by native PySpark `SparkSession` |
| 3 | `Job` class | `awsglue.job` | **Remove entirely** | No bookmark system in Synapse; job lifecycle managed by Synapse pipeline or notebook run |
| 4 | `getResolvedOptions` | `awsglue.utils` | **Remove entirely** | Replace with `mssparkutils.notebook.exit()` / widget parameters / pipeline parameters |
| 5 | `glueContext.create_dynamic_frame.from_catalog(database, table_name)` | `awsglue.context` | `spark.read.csv(adls_path, header=True, inferSchema=True)` or `spark.read.format("delta").load(...)` | Catalog table must be re-registered in Synapse catalog or replaced with direct ADLS path read |
| 6 | `DynamicFrame` (object type) | `awsglue.dynamicframe` | `pyspark.sql.DataFrame` | All DynamicFrame variables become standard DataFrames; no wrapper needed |
| 7 | `medicare_dyf.resolveChoice(specs=[("provider id","cast:long")])` | `awsglue.dynamicframe` | `df.withColumn("provider id", col("provider id").cast(LongType()))` | Cast returns `null` for non-castable values — identical semantics to Glue `cast:long` |
| 8 | `medicare_res.toDF()` | `awsglue.dynamicframe` | **Remove** — already a DataFrame | Conversion step is eliminated; work directly with DataFrame throughout |
| 9 | `DynamicFrame.fromDF(df, glueContext, name)` | `awsglue.dynamicframe` | **Remove** — no conversion needed | Eliminated; `apply_mapping` replacement operates directly on DataFrame |
| 10 | `udf(lambda x: x[1:], StringType())` | `pyspark.sql.functions` | `udf(lambda x: x[1:] if x and len(x) > 1 else None, StringType())` | **Must add null guard** — see Risk R1; UDF syntax is otherwise identical |
| 11 | `df.withColumn("ACC", chop_f(col("average covered charges")))` | PySpark (unchanged) | `df.withColumn("ACC", chop_f(col("average covered charges")))` | No change required beyond UDF null safety fix |
| 12 | `medicare_tmp.apply_mapping([...])` | `awsglue.dynamicframe` | `df.select(struct(...).alias("provider"), struct(...).alias("charges"), col(...).alias(...))` | Most complex replacement — see Step 6 in migration plan |
| 13 | `glueContext.write_dynamic_frame.from_options(frame, connection_type="s3", connection_options={"path": s3_path}, format="parquet")` | `awsglue.context` | `df.write.mode("overwrite").parquet(adls_path)` | Replace S3 path with ADLS Gen2 `abfss://` URI; use Managed Identity or linked service auth |
| 14 | `sys` (imported, unused) | Python stdlib | **Remove** | Not used in source or target |

## 5. Step-by-Step Migration Plan

---

### STEP 0 — Pre-Migration Infrastructure Setup

**Complexity:** MEDIUM  
**Developer Approval Required:** ✅ Yes  
**Estimated Time:** 1–2 hours

#### Actions

| # | Action | Detail |
|---|---|---|
| 0.1 | Provision Azure Synapse Analytics workspace | Ensure workspace exists with a Spark pool (recommended: `Standard_DS3_v2`, 3–10 nodes, Spark 3.3+) |
| 0.2 | Provision ADLS Gen2 storage account | Create containers: `source` (input Medicare CSV) and `target` (output Parquet) |
| 0.3 | Upload source data to ADLS Gen2 | Transfer Medicare CSV data from S3 (`payments.medicare` catalog table backing store) to `abfss://source@<account>.dfs.core.windows.net/medicare/` |
| 0.4 | Configure Managed Identity access | Grant Synapse workspace Managed Identity `Storage Blob Data Contributor` on both ADLS Gen2 containers |
| 0.5 | Create Synapse Linked Service for ADLS Gen2 | Define linked service using Managed Identity authentication; test connectivity |
| 0.6 | (Optional) Register table in Synapse Lake Database | If catalog-style access is required, register the Medicare CSV as an external table in Synapse Lake Database using `spark.sql("CREATE TABLE ...")` |
| 0.7 | Define output path variable | Set `output_path = "abfss://target@<account>.dfs.core.windows.net/output-dir/medicare_parquet"` |

#### Notes
- The Glue Data Catalog table `payments.medicare` has no direct equivalent. The backing S3 data must be physically migrated to ADLS Gen2. The catalog reference is replaced by a direct path read or a Synapse Lake Database table registration.
- If the source data schema is well-defined, prefer `spark.read.csv(..., schema=defined_schema)` over `inferSchema=True` to avoid type inference inconsistencies that originally caused the `provider id` choice type issue in Glue.
