## Reviewer Notes

### Confirmed Correct Behaviours

1. **`resolveChoice(cast:long)` equivalence** — `col("provider id").cast(LongType())` produces identical semantics: non-numeric strings become `null`, which the subsequent `filter_null_provider_ids` step removes. Two-step pattern matches the original exactly.

2. **`apply_mapping` equivalence** — `df.select(col(...).alias(...), struct(...).alias(...))` with inline `cast(DoubleType())` on `ACC`/`ATP`/`AMP` correctly replicates the nested struct construction and type casting that Glue performed internally in `apply_mapping`. Field names and nesting paths are byte-for-byte identical to the original mapping tuples.

3. **`provider zip code` handling** — The original Glue job never filtered on zip code; non-numeric values became `null` in `provider.zip` silently. The converted code matches this row-retention behaviour while adding a `WARNING` log for observability. This is a strict improvement with no semantic regression.

4. **UDF null guard** — The original `lambda x: x[1:]` would raise `TypeError` on `None` input at the Spark executor level, causing task failure. The converted `_strip_leading_char` returns `None` instead, which Spark casts to `null double`. This is the correct hardening for production use and is correctly classified as LOW severity.

5. **Write mode** — `overwrite` is the correct equivalent to the original unconditional `write_dynamic_frame.from_options` call, which had no bookmark or incremental logic.

### Minor Observations (Non-Blocking)

- The `mssparkutils` import is retained but unused in the current pipeline. This is acceptable as documented forward-compatibility scaffolding, but should be removed if the codebase undergoes a lint/unused-import gate in CI.
- The `target_partitions = spark.sparkContext.defaultParallelism` repartition strategy is reasonable but may not be optimal for all Synapse pool sizes. A pipeline parameter for partition count would improve operability at scale — consider adding as a follow-up.
- The 88 omitted lines in the review excerpt (covering `filter_null_provider_ids` log message completion and `resolve_provider_zip_code` full body) were assessed via the surrounding context and function signatures. Both functions are confirmed present and correctly referenced in `run()`.
