## Conversion Notes

### Fix 1 — `_strip_leading_char` null guard alignment (MEDIUM, lines 96–107)

**Problem:** The original guard was `if value is None or len(value) == 0: return None`. This diverged from the source lambda `x[1:]`, which only raised `TypeError` on `None` and returned an empty string `''` for a single-character input. The extra `len(value) == 0` branch silently converted empty strings to `None`, which then cast to `null` doubles in `build_nested_schema` — masking potential data-quality issues.

**Fix applied:** The guard was tightened to `if value is None: return None` only, exactly matching the original lambda's null-safety contract. Empty strings now pass through to `value[1:]` (returning `''`), which Spark's `cast(DoubleType())` will convert to `null` via its normal cast-failure path — identical to the original behaviour. The docstring was updated to document this decision explicitly and note that if empty-string data-quality detection is desired in future, a `logger.warning` branch should be added rather than silently returning `None`.

### Fix 2 — Repartition moved to after `filter_null_provider_ids` (LOW, lines 330–342)

**Problem:** The `repartition(target_partitions)` call was placed immediately after `read_source`, before `resolve_provider_id` and `filter_null_provider_ids`. This caused the shuffle to operate on the full unfiltered dataset, including rows that would be discarded by the null filter. For large inputs with many non-numeric provider IDs this wastes significant shuffle I/O.

**Fix applied:** The repartition call was moved to after `filter_null_provider_ids` in `run()`. The pipeline now executes in the order: `read_source` → `resolve_provider_id` → `filter_null_provider_ids` → `repartition` → `strip_currency_symbols` → `build_nested_schema` → `write_parquet`. The docstring for `run()` was updated to reflect the new step ordering and to explain the rationale (shuffle operates only on the already-reduced dataset). The `read_source` docstring was also updated to remove the reference to repartitioning happening immediately after the read.
