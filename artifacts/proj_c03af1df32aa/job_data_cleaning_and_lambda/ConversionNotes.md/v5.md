## Conversion Notes

### Fix 1 — `schema_fidelity` (lines 68–82): Explicit documentation of intentional `StringType` for `provider zip code`

**What changed:**
The `SOURCE_SCHEMA` block already declared `provider zip code` as `StringType`, but there was no explanation for why a column that was `long` in the original Glue source schema was being read as a string. This created a silent divergence risk.

**Fix applied:**
- Added a detailed module-level `NOTE` comment block immediately above `SOURCE_SCHEMA` explaining that `provider zip code` is *intentionally* `StringType` to enable a controlled, observable cast rather than a silent CSV-reader coercion.
- Added an inline `# Intentionally StringType — see module-level NOTE above.` comment on the `provider zip code` `StructField` line so the intent is visible at the point of declaration.

### Fix 2 — `transformations` (lines 261–265): New `resolve_provider_zip_code` function with data-quality logging and null-row filtering

**What changed:**
Previously, `provider zip code` was cast to `LongType` silently inside `build_nested_schema` via `col('provider zip code').cast(LongType()).alias('zip')`. Any non-numeric ZIP string would produce a `null` in `provider.zip` with no warning, no count, and no row dropped — a data-corrupt output that was structurally valid but behaviourally wrong relative to the original Glue job.

**Fix applied:**

1. **New function `resolve_provider_zip_code(df)`** added between `filter_null_provider_ids` and `strip_currency_symbols`. It:
   - Counts rows where `col("provider zip code").cast(LongType()).isNull()` AND the original value was not already `null` (i.e., genuinely non-numeric strings, not pre-existing nulls).
   - Emits a `logger.warning(...)` with the exact bad-row count if any are found, making the issue visible in Synapse Monitor and Log Analytics.
   - Applies the cast via `withColumn`, then filters out all `null` ZIP rows (covering both pre-existing nulls and cast-failure nulls), mirroring the `filter_null_provider_ids` drop-row business rule.

2. **`build_nested_schema` updated**: The redundant `col("provider zip code").cast(LongType())` inside the `struct(...)` expression was replaced with a plain `col("provider zip code").alias("zip")` because the column is already `LongType` and null-free by the time `build_nested_schema` is called. This eliminates the silent-null risk entirely at the struct-construction stage.

3. **`run()` orchestration updated**: `resolve_provider_zip_code` is called after repartitioning and before `strip_currency_symbols`, with the result bound to `zip_resolved_df`. The docstring step list is updated to reflect the new step 5.

4. **`build_nested_schema` docstring updated** to document that both `provider id` and `provider zip code` arrive as `LongType` with nulls already removed, so no cast is needed inside the struct.
